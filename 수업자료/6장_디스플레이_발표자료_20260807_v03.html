실습 1 · 개요

4자리 숫자 표시기

무엇을 하는 부품?

숫자나 시간을 보여주는 부품입니다. 0부터 9까지의 숫자와 간단한 글자를 표시할 수 있습니다.

어떻게 생겼나?

네 개의 숫자 자리로 이루어져 있고, 한 자리마다 7개의 LED가 들어 있습니다.

어디에 쓰나?

ESP32에 연결하면 시계, 게임 점수판, 타이머처럼 여러 가지로 활용할 수 있습니다.

전자레인지·알람시계에서 매일 보는 바로 그 화면

첫 번째 주인공, 4자리 숫자 표시기입니다. 어디서 많이 본 것 같지 않아요? 맞아요, 전자레인지 시간 표시, 디지털 알람시계가 전부 이 부품입니다.

구조는 간단합니다. 숫자 자리가 네 개 있고, 한 자리마다 LED가 7개 들어 있어요. "겨우 LED 7개로 어떻게 0부터 9까지 다 그리지?"라는 게 오늘 첫 번째 퀴즈입니다. 다음 장에서 답을 확인해 봅시다.

실습 1 · 원리 ①

7세그먼트 — LED 7개로 그리는 숫자

획 a~g + 소수점(dp) · 자동으로 0→9 반복

'8'자 모양 배치

숫자 한 자리는 막대 모양 LED 7개(획·세그먼트)를 '8'자 모양으로 배치한 것입니다.

켜고 끄는 조합 = 숫자

7개의 획 중 어느 것을 켜고 끄느냐의 조합으로 0부터 9까지의 숫자 모양을 그립니다.
예 : 위·오른위·오른아래 획만 켜면 숫자 '7'

소수점 LED는 덤

획 7개에 더해 소수점용 LED가 따로 있어, 소수가 있는 숫자도 나타낼 수 있습니다.

네 자리를 나란히

이런 한 자리 표시기를 네 개 붙여 0부터 9999까지의 수를 보여 줍니다.

답은 바로 이겁니다. LED 7개를 '8'자 모양으로 배치해 놓은 거예요. 획마다 a부터 g까지 이름이 붙어 있습니다.

왼쪽 화면을 보세요. 지금 0부터 9까지 차례로 바뀌고 있죠? 숫자가 바뀌는 게 아니라 켜지는 획의 조합이 바뀌는 겁니다. 예를 들어 위, 오른쪽 위, 오른쪽 아래 — 세 획만 켜면 '7'이 됩니다.

여기에 소수점 LED가 하나 더 있어서 소수도 표현할 수 있고, 이 한 자리를 네 개 붙이면 0부터 9999까지 표시할 수 있습니다. 이 부분은 시험에 나올 수 있는 핵심 원리니까 꼭 기억하세요.

실습 1 · 원리 ②

I2C — 전선 2가닥으로 나누는 대화

ESP32
SDA · 내용(데이터)을 보내는 선
TM1650
ESP32
SCL · 박자(클록)를 맞추는 선
TM1650

보내는 내용은 두 가지

① 주소 — 여러 부품 중 "누구에게 말할지" 받을 곳을 정하고
② 데이터 — 그 부품에게 실제 내용을 담아 보냅니다

클록이 박자를 맞춘다

SCL 선이 일정한 박자(클록)를 보내, 보내는 쪽과 받는 쪽이 같은 박자에 맞춰 비트를 주고받습니다.

한 쌍의 선에 여러 부품

같은 두 가닥에 부품 여러 개를 이을 수 있어, 먼저 '주소'로 어느 부품에게 말할지 정합니다.

배선이 간단해진다

부품이 늘어도 선 두 가닥만으로 여러 부품을 제어할 수 있습니다.

그럼 ESP32는 이 표시기와 어떻게 대화할까요? I2C라는 통신 방식을 씁니다. 핵심은 단 두 가닥의 선이에요. SDA로는 실제 내용을 보내고, SCL로는 박자를 맞춥니다.

박자가 왜 필요할까요? 줄넘기 2인 뛰기를 생각해 보세요. 박자가 안 맞으면 걸려 넘어지죠. 데이터도 마찬가지로, 보내는 쪽과 받는 쪽이 같은 박자로 읽어야 정확히 전달됩니다.

그리고 보내는 내용은 항상 주소 먼저, 데이터 나중입니다. 같은 두 가닥에 부품을 여러 개 매달 수 있으니까, "이건 너한테 하는 말이야"라고 주소로 콕 집은 다음 내용을 보내는 거예요. 덕분에 부품이 늘어도 배선은 두 가닥 그대로! 이게 I2C의 최대 장점입니다.

실습 1 · 원리 ③

TM1650이 알아듣는 두 가지 주소

0x48 — 화면 설정 주소

밝기와 표시 방법을 정하는 명령을 받습니다.

76543210

bit[6:4] 밝기(000이 가장 밝음) · bit[3] 소수점 켜기 · bit[0] 화면 켜기

0x68 … — 숫자 자리 주소

각 자리에 표시할 숫자 데이터를 받습니다. 자리마다 주소가 하나씩 있습니다.

💡 0x가 뭐예요?

0x로 시작하는 수는 16진수 — 컴퓨터가 자주 쓰는 숫자 표기 방식입니다. 0x48은 10진수로 72입니다.

우리 표시기를 움직이는 칩 이름이 TM1650인데, 이 칩이 알아듣는 주소는 딱 두 종류입니다.

첫째, 0x48 화면 설정 주소. "밝기를 얼마로 해라, 화면을 켜라" 같은 설정 명령을 받는 곳이에요. 화면의 비트 표를 보면, 6~4번 비트가 밝기, 3번이 소수점, 0번이 화면 켜기입니다. 재미있는 건 밝기 000이 가장 밝다는 것!

둘째, 0x68 같은 숫자 자리 주소. 실제로 표시할 숫자 데이터를 받는 곳입니다. 자리가 네 개니까 주소도 자리마다 있어요.

아, 그리고 0x라는 표기가 낯설죠? 이건 16진수라는 뜻입니다. 컴퓨터가 즐겨 쓰는 표기법이고, 0x48은 10진수로 72예요. 정보 교과에서 배운 진법 변환이 여기서 쓰입니다.

실습 1 · 원리 ④

비트 하나 = 획 하나

숫자 모양은 8개 비트로

데이터 1바이트(8비트)의 비트 하나가 획 하나. 1이면 켜지고 0이면 꺼집니다.

예시

자리 주소 0x68에 0x7F를 보내면 → 획 7개 + 소수점이 켜져 점이 있는 8이 표시됩니다.

직접 계산할 필요는 없어요

이 신호들은 TM1650 라이브러리가 대신 처리합니다.
displayFloatNum(9999) 한 줄이면 9999가 표시됩니다.

dpgfedcba

0x7F = 0111 1111 → "8." 표시

그럼 데이터는 어떻게 생겼을까요? 아주 우아합니다. 1바이트, 즉 8개의 비트가 있는데 비트 하나가 획 하나와 1:1로 연결돼 있어요. 비트가 1이면 그 획이 켜지고, 0이면 꺼집니다.

화면의 예시를 보세요. 0x68 자리에 0x7F를 보내면, 이진수로 0111 1111이니까 일곱 개 획이 다 켜지고 소수점까지 켜져서 '점이 있는 8'이 됩니다.

"이걸 다 외워서 계산해야 하나요?" 걱정 마세요. 라이브러리가 대신 해 줍니다. 우리는 displayFloatNum(9999) 한 줄만 쓰면 돼요. 하지만 그 한 줄 뒤에서 무슨 일이 일어나는지 아는 사람과 모르는 사람은 문제 해결 능력이 완전히 다릅니다.

실습 1 · 코드

핵심 코드 digit_display.ino

실습코드 폴더 · digit_display.ino
// ① 선언부 — 라이브러리와 핀 설정
#include "TM1650.h"
TM1650 display(22, 21);   // CLK=IO22, DIO=IO21

void setup() {
  // ② 0~3번 네 자리를 모두 지운다
  for (int i = 0; i < 4; i++)
    display.clearBit(i);
}

void loop() {
  // ③ 숫자 표시기에 9999를 표시
  display.displayFloatNum(9999);
}

①선언부 · 설정

숫자 표시기 라이브러리를 불러오고 CLK·DIO 핀(IO22·IO21)으로 객체를 만듭니다.

②setup( )

표시기의 0~3번 네 자리를 모두 지웁니다. (이전에 남은 표시 제거)

③loop( )

숫자 표시기에 9999를 표시합니다. loop는 계속 반복됩니다.

코드를 봅시다. 딱 세 부분입니다. 선언부에서 라이브러리를 불러오고 CLK는 IO22, DIO는 IO21 핀으로 객체를 만들어요.

setup에서는 0번부터 3번까지 네 자리를 전부 지웁니다. 전에 쓰던 값이 화면에 남아 있을 수 있으니 깨끗이 청소하는 거예요.

loop에는 displayFloatNum(9999) 한 줄. 이 한 줄이 아까 배운 주소와 데이터 신호를 모두 대신 만들어 줍니다. 코드가 짧다고 실망하지 마세요 — 원리를 알고 쓰는 한 줄은 열 줄의 가치가 있습니다. 코드는 AI에게 만들어 달라고 해도 되지만, 읽고 고칠 줄 아는 건 여러분 몫입니다.

도구 상자 가져오기 — #include

#include "TM1650.h"
TM1650 칩을 다루는 함수 묶음(라이브러리)을 통째로 가져온다
#include

"이 파일을 가져와라"라는 명령. 컴파일할 때 라이브러리 내용이 내 코드 앞에 통째로 붙는다.

"TM1650.h"

TM1650 제어 함수들이 들어 있는 파일. 이 줄이 없으면 displayFloatNum 같은 함수를 아예 쓸 수 없다.

digit_display.ino #include "TM1650.h" TM1650 display(22, 21); void setup() { for (int i = 0; i < 4; i++) display.clearBit(i); } void loop() { display.displayFloatNum(9999); }

먼저 도구 상자를 가져옵니다. #include는 "이 파일을 내 코드에 통째로 붙여라"라는 뜻이에요.

TM1650.h 안에 표시기를 다루는 함수가 다 들어 있습니다. 이 한 줄 덕분에 우리는 어려운 통신 코드를 직접 쓰지 않아도 됩니다.

실습 1 · 코드 해설 2 / 5

표시기 리모컨 만들기 — 핀 번호 두 개

TM1650 display(22, 21);
display라는 이름의 제어 객체(리모컨)를 만들며 연결 핀을 알려준다
display

앞으로 표시기에 명령을 내릴 때 쓸 이름. display.○○( ) 형태로 부른다.

22

CLK(박자) 핀. 데이터를 읽을 타이밍을 맞춰 주는 선 — ESP32의 22번 핀에 연결.

21

DIO(데이터) 핀. 실제 내용이 오가는 선. I2C의 SDA에 해당 — 21번 핀에 연결.

digit_display.ino #include "TM1650.h" TM1650 display(22, 21); void setup() { for (int i = 0; i < 4; i++) display.clearBit(i); } void loop() { display.displayFloatNum(9999); }

이 줄이 배선과 코드를 잇는 다리입니다. 괄호 안 숫자 두 개가 핀 번호예요.

첫 번째 22가 박자 선 CLK, 두 번째 21이 데이터 선 DIO. 실제 배선과 이 숫자가 다르면 아무것도 표시되지 않습니다. 순서도 중요해요.

실습 1 · 코드 해설 3 / 5

네 자리를 돌리는 반복문 — for

for (int i = 0; i < 4; i++)
자리 번호 0~3을 차례로 도는 4번 반복 — setup( ) 안에서 실행된다
int i = 0

시작값. 자리 번호가 0부터 시작하니까 i도 0부터. (컴퓨터는 0부터 센다!)

i < 4

계속 조건. i가 4가 되는 순간 멈춘다 → 0, 1, 2, 3으로 총 4번 실행.

i++

한 바퀴 돌 때마다 i를 1씩 증가. 0→1→2→3으로 자리를 옮겨 간다.

digit_display.ino #include "TM1650.h" TM1650 display(22, 21); void setup() { for (int i = 0; i < 4; i++) display.clearBit(i); } void loop() { display.displayFloatNum(9999); }

setup 안의 for문입니다. 세 칸으로 나눠 읽으면 쉬워요 — 시작, 조건, 증가.

i가 0부터 시작해서 4보다 작은 동안, 한 바퀴마다 1씩 커집니다. 그래서 0, 1, 2, 3 — 정확히 네 번. 자리도 네 개죠.

실습 1 · 코드 해설 4 / 5

자리 지우기 — clearBit

display.clearBit(i);
i번째 자리를 끈다 — 반복문과 합쳐져 네 자리 전부 청소
clearBit( )

한 자리를 지우는(끄는) 함수. 이전에 표시되던 값을 청소한다.

i

지울 자리 번호(0~3). for문이 돌 때마다 0, 1, 2, 3이 차례로 들어와 네 자리가 모두 지워진다.

digit_display.ino #include "TM1650.h" TM1650 display(22, 21); void setup() { for (int i = 0; i < 4; i++) display.clearBit(i); } void loop() { display.displayFloatNum(9999); }

반복문 안에서 실행되는 한 줄입니다. clearBit(i)는 i번째 자리를 지우라는 뜻.

i가 0, 1, 2, 3으로 바뀌며 네 번 실행되니까 결국 네 자리가 전부 깨끗해집니다. 쓰레기 값이 남지 않게 하는 준비 작업이에요.

숫자 표시 — displayFloatNum

display.displayFloatNum(9999);
9999를 네 자리에 표시 — loop( ) 안이라 끝없이 반복되어 화면이 유지된다
displayFloatNum( )

숫자를 자리별로 쪼개 자리 주소(0x68~0x6B)로 전송하는 일까지 몽땅 대신해 주는 함수.

9999

표시할 숫자. 12.34처럼 소수점도 가능 — 값을 바꿔서 직접 실험해 보자.

digit_display.ino #include "TM1650.h" TM1650 display(22, 21); void setup() { for (int i = 0; i < 4; i++) display.clearBit(i); } void loop() { display.displayFloatNum(9999); }

마지막 한 줄이 실제로 숫자를 띄우는 부분입니다. displayFloatNum은 9999를 쪼개 자리 주소로 하나씩 보내는 일까지 대신해 줍니다.

loop 안에 있으니 계속 다시 그려져서 화면이 유지돼요. 괄호 안을 12.34로 바꾸면 소수점까지 표시됩니다.

도트매트릭스 표시기

무엇을 하는 부품?

작은 LED를 가로세로 격자로 촘촘히 배열해, 켜고 끄는 점들로 글자나 그림을 표시하는 부품입니다.

어떻게 생겼나?

8×8로 배열된 LED 모듈입니다. 가로줄·세로줄마다 제어 핀이 있어 각 LED를 조절합니다.

어디에 쓰나?

ESP32로 제어하면 글자·숫자·간단한 그림을 표시할 수 있습니다. 게임기나 작은 화면, 전광판에도 쓰입니다.

지하철 전광판도 원리는 같습니다 — 점이 모여 그림

두 번째 주인공, 도트매트릭스입니다. 숫자 표시기가 "정해진 획"만 켤 수 있었다면, 이 친구는 점 64개를 자유롭게 켜고 끌 수 있어요. 그래서 숫자뿐 아니라 글자, 그림까지 그릴 수 있습니다.

버스 앞의 행선지 전광판, 지하철 안내판 — 전부 이 도트매트릭스를 크게 만든 겁니다. 점을 아주 촘촘히 박으면? 그게 바로 여러분이 보는 모니터와 스마트폰 화면이에요. 오늘 우리는 모든 화면의 조상님을 배우는 셈입니다.

잔상 효과

사람 눈에 남는 잔상 덕분에, 한 줄씩 켜도 8×8 그림 전체가 한꺼번에 켜진 것처럼 보입니다.

그런데 문제가 하나 있어요. LED가 64개인데, 선을 64가닥 쓸 수는 없잖아요? 그래서 행 8줄 + 열 8줄, 16개의 선으로 해결합니다. LED는 자기 행과 열이 동시에 선택될 때만 켜져요.

대신 한 번에 한 줄씩만 그립니다. 왼쪽 화면을 보세요. 파란 줄이 위에서 아래로 쓸고 지나가면서 한 줄씩 그리고 있죠? 실제 부품은 이걸 1초에 수백 번 반복합니다.

그런데 왜 우리 눈엔 전체가 켜진 것처럼 보일까요? 바로 잔상 때문입니다. 불꽃놀이 막대를 빙빙 돌리면 원이 그려져 보이는 것과 같은 원리예요. 영화가 정지 사진 24장으로 움직임을 만드는 것도 같은 원리입니다. 잔상, 시험 포인트입니다!

실습 2 · 원리 ②

MAX7219 — 64개 LED의 지휘자, SPI로 명령받다

전용 칩 MAX7219

64개 LED를 켜고 끄는 일(한 줄씩 스캔)을 대신 맡아 주는 도트매트릭스 전용 제어 칩입니다.

SPI 통신

데이터선(DIN)·클록선(CLK)·선택선(CS) 등 여러 가닥을 함께 쓰는 통신 방식. 클록 박자에 맞춰 DIN의 비트를 한 칸씩 칩 안으로 밀어 넣습니다.

선택선 CS

"지금 이 칩에게 말한다"를 알려 같은 선에 이은 다른 칩과 헷갈리지 않게 합니다.

I2C vs SPI 한눈 비교 ⭐

I2CSPI
선 개수2가닥 (SDA·SCL)여러 가닥 (DIN·CLK·CS…)
속도보통더 빠름
상대 지정주소로 지정선택선(CS)으로 지정
오늘의 부품TM1650 숫자 표시기MAX7219 도트매트릭스

64개 LED를 한 줄씩 쉬지 않고 그리는 일, ESP32가 직접 하려면 너무 바쁘겠죠? 그래서 MAX7219라는 전용 칩에게 통째로 맡깁니다. 우리는 "이 그림 그려 줘"라고 데이터만 넘기면 돼요.

이 칩과는 SPI로 통신합니다. 데이터선 DIN, 클록선 CLK, 선택선 CS — I2C보다 선이 많은 대신 한 번에 더 빠르게 보낼 수 있어서, 화면을 빠르게 바꾸는 데 알맞습니다.

오른쪽 비교표가 오늘 수업의 핵심 정리입니다. I2C는 선 2가닥에 주소로 상대를 정하고, SPI는 선이 많은 대신 빠르고 선택선 CS로 상대를 정합니다. 이 표는 그대로 시험에 낼 수 있으니 사진 찍지 말고 손으로 정리해 두세요.

실습 2 · 코드

핵심 코드 dot_matrix.ino

실습코드 폴더 · dot_matrix.ino
// ① 선언부 — 라이브러리 · 핀 · 그림 데이터
#include <LedControl.h>
LedControl lc(23, 18, 15, 1); // DIN, CLK, CS
byte IMAGES[8] = { /* 하트 데이터 */ };

void setup() {
  lc.shutdown(0, false);  // ② 절전 모드 해제(깨우기)
  lc.setIntensity(0, 8);  //    밝기 중간으로
  lc.clearDisplay(0);     //    화면 지우기
}

void loop() {
  // ③ 하트 데이터를 한 줄씩 8번 그린다
  for (int row = 0; row < 8; row++)
    lc.setRow(0, row, IMAGES[row]);
}

①선언부 · 설정

라이브러리를 불러오고 DIN·CLK·CS 핀과 하트 모양 데이터를 정의합니다.

②setup( )

MAX7219를 깨우고(절전 해제), 밝기를 중간으로 맞춘 뒤 화면을 지웁니다.

③loop( )

IMAGES 배열 값을 한 줄씩 8번 그려 하트를 완성하고, 처음으로 돌아가 계속 반복합니다.

코드 구조는 숫자 표시기와 판박이입니다. 선언부에서 라이브러리, 핀 번호, 그리고 아까 만든 하트 데이터를 준비합니다.

setup에서 하는 일이 세 가지예요. MAX7219는 처음에 절전 모드로 잠들어 있어서 먼저 깨워야 합니다. 그다음 밝기를 중간으로 맞추고, 화면을 깨끗이 지웁니다.

loop에서는 for 반복문이 IMAGES 배열을 한 줄씩 꺼내 8번 그리면 하트가 완성됩니다. 8줄을 다 그리면 처음으로 돌아가 같은 그림을 계속 그리고요. setup은 한 번, loop는 무한 반복 — 이 구조는 아두이노 계열 코드의 공통 뼈대입니다.

byte

64개 점을 전부 끄는 함수. 실습 1의 clearBit와 같은 "청소" 역할.

0

모듈 번호. setup 세 줄의 첫 인자가 전부 0인 이유 — 모듈이 하나라서.

dot_matrix.ino #include <LedControl.h> LedControl lc(23, 18, 15, 1); byte IMAGES[8] = { B01100110, B11111111, … }; void setup() { lc.shutdown(0, false); lc.setIntensity(0, 8); lc.clearDisplay(0); } void loop() { for (int row = 0; row < 8; row++) lc.setRow(0, row, IMAGES[row]); }

setup의 마지막 줄, 화면 청소입니다. 이전에 그려져 있던 점이 남지 않게 64개 점을 전부 끕니다.

setup 세 줄을 묶어서 외웁시다 — "깨우고, 밝기 맞추고, 지우고".

실습 2 · 코드 해설 7 / 8

8줄을 도는 반복문 — for

for (int row = 0; row < 8; row++)
매트릭스의 8줄을 위에서부터 차례로 도는 반복문
int row = 0

시작값. 맨 윗줄이 0번 줄.

row < 8

계속 조건. 0~7로 총 8번 — 줄이 8개니까.

row++

한 바퀴마다 다음 줄로 내려간다.

dot_matrix.ino #include <LedControl.h> LedControl lc(23, 18, 15, 1); byte IMAGES[8] = { B01100110, B11111111, … }; void setup() { lc.shutdown(0, false); lc.setIntensity(0, 8); lc.clearDisplay(0); } void loop() { for (int row = 0; row < 8; row++) lc.setRow(0, row, IMAGES[row]); }

loop로 왔습니다. 실습 1에서 본 for문과 구조가 똑같죠? 이번엔 변수 이름이 row, 줄 번호입니다.

0번 줄부터 7번 줄까지 여덟 줄을 위에서부터 차례로 돕니다. 조건이 왜 row < 8인지 이제 설명할 수 있죠?

실습 2 · 코드 해설 8 / 8

한 줄 그리기 — setRow

lc.setRow(0, row, IMAGES[row]);
row번째 줄에 배열 row번째 칸을 그린다 — 8번 반복하면 하트 완성
0

모듈 번호. 오늘도 변함없이 첫 번째 모듈.

row

그릴 줄 번호(0~7). for문이 돌 때마다 다음 줄로.

IMAGES[row]

그 줄에 그릴 점 8개 데이터. row가 0이면 B01100110 → 비트가 그대로 점이 된다.

dot_matrix.ino #include <LedControl.h> LedControl lc(23, 18, 15, 1); byte IMAGES[8] = { B01100110, B11111111, … }; void setup() { lc.shutdown(0, false); lc.setIntensity(0, 8); lc.clearDisplay(0); } void loop() { for (int row = 0; row < 8; row++) lc.setRow(0, row, IMAGES[row]); }

핵심 한 줄입니다. setRow는 "0번 모듈의 row번째 줄에 IMAGES[row]를 그려라"예요.

row가 0이면 첫째 줄에 B01100110, 1이면 둘째 줄에 B11111111… 여덟 번 돌면 하트 완성. 배열 한 칸이 화면 한 줄 — 이 대응만 잡히면 끝입니다. IMAGES만 바꾸면 그림이 바뀌어요. 연습 문제 2번의 답이기도 합니다.

8줄을 다 그리면 loop가 처음부터 다시 시작돼 같은 하트를 계속 그립니다. 그래서 화면이 유지되는 거예요.

배선입니다. SPI라서 통신선이 세 가닥이에요. DIN은 IO23, CLK는 IO18, CS는 IO15. 전원까지 합치면 다섯 가닥입니다. 아까 I2C보다 한 가닥 많죠? 그 대신 속도를 얻은 겁니다.

코드를 올리면 화면처럼 하트가 나타납니다. 하트가 뜨면 기본 미션 성공!

그다음이 진짜 재미입니다. dotmatrixtool에서 자기 이니셜이나 좋아하는 아이콘을 그려서 IMAGES 배열만 바꿔 보세요. 세상에 하나뿐인 나만의 전광판이 됩니다. 실습 시간 15분 드릴게요. 다 만든 모둠은 화면을 들고 인증샷!

확인 학습 · 정답

정답과 해설

Q1 · 정답

9999가 계속 표시됩니다

loop( )는 끝없이 반복되며 매번 9999를 다시 표시하므로, 화면에는 늘 9999가 떠 있습니다.

Q2 · 정답

그려지는 그림(켜지는 점들의 모양)이 달라집니다

IMAGES 한 칸 = 매트릭스 한 줄. 1인 비트는 켜진 점, 0은 꺼진 점이므로, 값을 바꾸면 다른 모양이 나타납니다.

📝 시험 포인트 정리

① 7세그먼트: 획 7개의 켜고 끄는 조합 = 숫자  ② I2C(2선·주소) vs SPI(여러 선·CS·고속)  ③ 비트 1 = 켜짐, 0 = 꺼짐  ④ 한 줄씩 스캔 + 잔상 → 전체 그림  ⑤ loop( )는 무한 반복

1번 정답 — 9999가 계속 표시됩니다. 포인트는 loop가 무한 반복이라는 것. 한 번 그리고 끝나는 게 아니라 매번 9999를 다시 그리기 때문에, 화면엔 늘 9999가 떠 있는 거예요.

2번 정답 — 그림이 달라집니다. IMAGES 한 칸이 매트릭스 한 줄이고, 1인 비트는 켜진 점, 0인 비트는 꺼진 점이니까요. 값을 바꾸는 순간 다른 모양이 나타납니다.

아래 다섯 가지가 오늘의 시험 포인트입니다. 특히 I2C와 SPI 비교, 그리고 잔상 원리는 지필평가 단골이니 꼭 자기 손으로 정리해 두세요.
